1. The Salesforce loop, what to expect

Typical MTS / SMTS (India + US) loop, compiled from public candidate reports. Exact rounds vary by team and level, so confirm with the recruiter, but the shape below has held for years.

StageFormatWhat they are really scoring
Online assessmentHackerRank, 60 to 90 min, 2 to 3 problems (easy-medium to medium), sometimes MCQs on OOP / DB / OSCan you finish clean code under a clock. Do you handle edge cases without being told.
Phone / virtual screen45 to 60 min, 1 to 2 LeetCode-medium problems, shared editorCommunication while coding, pattern recognition speed, correctness on first run.

Onsite: Coding round 2 / "Design + code"Practical problem: LRU, rate limiter, log merge, scheduler, parser. Often OOP-flavouredProduction-quality code: classes, naming, error handling, extensibility. They love "now make it thread-safe / now it is a stream".
Onsite: System / Low-level design45 to 60 min. LLD (parking lot, elevator, notification, file system) for MTS; HLD (URL shortener, rate limiter service, feed, multi-tenant SaaS) for SMTS+Requirements clarification, clear entities and APIs, trade-offs, scale numbers, failure handling.
Hiring manager / Behavioral45 min. Past projects deep dive, conflict, ownership, "why Salesforce"Ownership, impact with numbers, values alignment (Trust, Customer Success, Innovation, Equality, Sustainability), collaboration.
Salesforce flavour: compared with Google-style loops they lean more practical. Expect string parsing, intervals, hashing, heaps, LRU / caches, rate limiting, log processing, tree traversals, matrix/grids, and "design a small class with these operations in O(1)". Hard DP and obscure graph algorithms are rarer, but binary search on answer, topological sort and Union-Find do appear.

The interview script (say it out loud, every problem)

  1. Restate the problem in one sentence. Confirm input/output types and an example.
  2. Constraints: N, value range, negatives, duplicates, sortedness, memory, streaming. Read N first.
  3. Brute force with its complexity, in 2 sentences. Then why it is too slow.
  4. Pattern + invariant: "contiguous with a constraint, so sliding window; invariant: window always valid".
  5. Walk one example by hand before typing.
  6. Code top-down: helper signatures first, then bodies. Name things. No single-letter variables outside loops.
  7. Test: trace the example, then empty, single, all-equal, negatives, max size. Fix silently, announce the fix.
  8. Complexity time + auxiliary space, and why. Then ask: "want the follow-up where X changes?"
